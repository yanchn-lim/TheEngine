TheEngine / build and run

Build and run

Build the Visual Studio project, select one graphics backend, and start the engine. The repository contains its third-party source dependencies.

Requirements

  • Visual Studio 2022 with the C++ desktop workload.
  • A 64-bit Windows build environment.
  • The Vulkan SDK for the Vulkan backend.
  • A graphics driver that supports OpenGL 4.6 or Vulkan 1.3.

The project uses the v143 toolset and C++20. It includes GLFW, GLAD, GLM, ImGui, stb, tinyobjloader, and Vulkan headers through the project file.

Build the engine

  1. Open GameEngine/GameEngine.sln.
  2. Select an x64 configuration.
  3. Build the GameEngine project.
  4. Start the executable from Visual Studio.

Debug builds call Tests::RunGraphicsApiTests() during engine startup. A test failure can stop startup before the window loop begins.

Select a backend

Engine::renderbackend selects the graphics backend. The current default is Vulkan.

// GameEngine/src/core/engine.hpp
Graphics::RendererBackend renderbackend = Graphics::RendererBackend::VULKAN;

// select this value to use OpenGL
// Graphics::RendererBackend renderbackend = Graphics::RendererBackend::OPENGL;

The selection controls window setup, graphics device creation, and ImGui backend creation. User render code does not change.

Initialization order

  1. The window initializes GLFW for the selected backend.
  2. The graphics factory creates the matching IGraphicsDevice.
  3. The device creates its native context and graphics resources.
  4. The engine creates RenderWorld, RenderResourceManager, and Renderer.
  5. The ImGui factory creates the matching IImGuiBackend.
  6. The engine enters the update loop.

GameEngine/src/main.cpp is the application entry point. GameEngine/src/core/engine.cpp owns the lifecycle.

Update loop

  1. The profiler and memory tracker start a frame.
  2. The engine polls window events and updates time.
  3. Game code updates persistent render data or submits one-frame draws.
  4. Renderer::Render records the scene pass.
  5. The ImGui backend records the debug interface.
  6. Renderer::EndFrame submits graphics work.
  7. Renderer::Present presents the swapchain image.
  8. The profiler and memory tracker finish the frame.

The loop uses FrameStatus after each graphics operation. It skips an invalid frame. It stops after DeviceLost or Fatal.

Shutdown order

The engine first waits for graphics work to stop. It then destroys ImGui, renderer resources, render data, the graphics device, and the window. This order prevents a subsystem from using an object that its owner already destroyed.
