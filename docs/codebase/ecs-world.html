ECS::World

Owns entities and typed component pools, and provides the complete public ECS API.

Entity operations

CreateEntity()
Creates a live entity. It reuses a free slot when available and changes that slot's generation.
GetEntityCount()
Returns the number of live entities.
RemoveEntity(entity)
Removes every component owned by the entity, marks it dead, and returns its ID to the free-slot list. A dead or stale handle has no effect.
IsEntityAlive(entity)
Returns true only when the ID is in range and both the slot state and generation match.

Component operations

AddComponent<T>
Copies a component into its typed pool and returns the stored reference. It throws when the entity is not alive or already has that component type.
GetComponent<T>
Returns a mutable or const reference. It throws when the entity is not alive or the component is absent.
TryGetComponent<T>
Returns a pointer when the entity is alive and owns the component. Otherwise, it returns nullptr.
HasComponent<T>
Returns whether a live entity owns the component.
RemoveComponent<T>
Uses swap removal and returns whether a component was removed. It returns false for dead entities, missing pools, and absent components.

Component template arguments must be unqualified object types. Do not pass const, volatile, or reference types.

Component views

template<typename Component>
struct ComponentView {
    std::span<const Entity> entities;
    std::span<Component> components;
};

The two spans are aligned: entities[index] owns components[index]. They are empty when no pool exists.

The spans are non-owning. Do not retain a view across component addition, component removal, or entity removal that can change the same pool.

ForEach

ForEach requires at least one component type. It returns without invoking the callback when any requested pool does not exist.

The query selects the smallest requested pool, then checks the other pools with sparse lookups. Mutable worlds pass mutable component references. Const worlds pass const component references.

world.ForEach<Position, Velocity>(
    [](ECS::Entity entity, Position& position, Velocity& velocity) {
        // Change values only. Do not change entity structure here.
    });

const ECS::World& readOnlyWorld = world;
readOnlyWorld.ForEach<Position, Velocity>(
    [](ECS::Entity entity,
       const Position& position,
       const Velocity& velocity) {
        // Read-only query.
    });

Failure and invalidation rules

  • Use throwing access when absence is an error. Use TryGetComponent, HasComponent, or the Boolean remove result when absence is expected.
  • Dense order can change after removal.
  • Component references can be invalidated when adding the same component type reallocates its dense vector.
  • Views become invalid when their pool changes structurally.
  • ForEach callbacks must not add or remove entities or components.
