TheEngine / ECS

Entity component system

ECS::World owns generation-checked entities and sparse-set component storage. Systems read components through views or typed queries.

Use ECS::World as the public API. Component pools and type IDs are internal storage details.

Architecture

Entity→ ECS::World→ component pool→ view or ForEach
ECS::World
Owns entity slots, component pools, component access, views, and queries.
ECS::Entity
Contains an entity ID and generation. Both values must be nonzero.
ECS::ComponentView<T>
Contains aligned spans of entities and components without owning their storage.
ECS::Internal::ComponentPool<T>
Stores one component type in dense arrays with a sparse entity-to-index map.

Entity lifecycle

World::CreateEntity returns an ID and generation. Removing an entity clears all of its components, marks its slot dead, and makes the ID available for reuse.

When a slot is reused, its generation changes. World::IsEntityAlive compares both fields, so an older handle does not address the replacement entity during normal generation reuse.

ECS::World world;
ECS::Entity entity = world.CreateEntity();

if (world.IsEntityAlive(entity)) {
    world.RemoveEntity(entity);
}

Component storage

Each component type has one sparse-set pool. The dense entity array and dense component array use the same index. The sparse array maps an entity ID to that dense index.

Removal swaps the last dense element into the removed position, updates its sparse index, and then shrinks both dense arrays. This operation is constant-time, but dense order is not stable.

  • Lookup and membership checks are constant-time.
  • Dense iteration is contiguous and cache-friendly.
  • Adding a component copies the supplied component into its pool.
  • Adding the same component type twice throws an exception.

Single-component views

GetComponentView<T> returns aligned entity and component spans. A mutable world returns mutable components. A const world returns const components. If the component pool does not exist, both spans are empty.

auto view = world.GetComponentView<Position>();

for (std::size_t index = 0; index < view.components.size(); ++index) {
    ECS::Entity entity = view.entities[index];
    Position& position = view.components[index];
    position.x += 1.0f;
}

A view does not own storage. Adding or removing the viewed component type, or removing an entity that has it, can invalidate both spans.

Multi-component queries

ForEach<Components...> finds every requested pool and selects the smallest pool as the candidate set. It uses sparse lookups in the other pools and invokes the callback only when an entity has every requested component.

world.ForEach<Position, Velocity>(
    [](ECS::Entity entity, Position& position, Velocity& velocity) {
        position.x += velocity.x;
        position.y += velocity.y;
    });

The const overload passes const component references. Template argument order determines callback argument order, but it does not determine which pool drives iteration.

Do not add or remove entities or components inside a ForEach callback. Structural changes can invalidate the dense entity span being iterated.

Complete example

struct Position {
    float x = 0.0f;
    float y = 0.0f;
};

struct Velocity {
    float x = 0.0f;
    float y = 0.0f;
};

ECS::World world;
ECS::Entity moving = world.CreateEntity();
ECS::Entity stationary = world.CreateEntity();

world.AddComponent(moving, Position{ 10.0f, 5.0f });
world.AddComponent(moving, Velocity{ 1.0f, -0.5f });
world.AddComponent(stationary, Position{ 0.0f, 0.0f });

world.ForEach<Position, Velocity>(
    [](ECS::Entity, Position& position, Velocity& velocity) {
        position.x += velocity.x;
        position.y += velocity.y;
    });

The query updates moving and skips stationary because it has no Velocity.

Current limits

  • The world is not thread-safe.
  • There is no scheduler, command buffer, serialization layer, lifecycle event stream, or query cache.
  • Structural changes are not supported during view or query iteration.
  • Component references and spans can be invalidated by dense-vector reallocation or swap removal.
  • The add API copies components; direct emplacement and move-only components are not supported.
