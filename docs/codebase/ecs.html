TheEngine / ECS integration

ECS integration

Components store render source data. RenderSystem converts component lifecycle events into persistent RenderWorld instances.

The adapter code is present. A complete ECS query or lifecycle dispatcher does not call it yet.

System boundary

entity components→ RenderSystem→ persistent RenderWorld instance

The component remains the serialized source of truth. RenderWorld owns the runtime copy that the renderer reads.

Classes and structures

Systems::RenderSystem
Converts component lifecycle events into persistent render instances.
SpriteComponent
Stores serialized sprite data and a runtime render connection.
MeshRendererComponent
Stores serialized mesh data and a runtime render connection.
Transform2D
Provides the model matrix used by render descriptions.

Component types

SpriteComponent

The serialized fields define visibility, texture, material, color, UV bounds, pivot, and sorting order.

The runtime fields store a RenderInstanceHandle and a render version. Do not serialize these runtime fields.

MeshRendererComponent

The serialized fields define mesh, material, layer mask, and visibility. The runtime fields store a RenderInstanceHandle and a render version.

Transform2D

The transform provides the model matrix for the render description. RenderSystem combines it with the render component data.

Lifecycle summary

For the complete contract, read the RenderSystem reference.

Add(entityId, transform, component, ...)
Builds a render description, creates a persistent instance, and stores its handle in the component.
Update(entityId, transform, component, ...)
Applies changed transform or component data to the existing instance.
Remove(component)
Destroys the persistent instance and clears its runtime connection.

The sprite overload accepts a fallback material. This value lets the system submit a sprite when the component does not select its own material.

Connect an ECS

The ECS integration must detect three events.

  1. When a matching component enters the query, call Add.
  2. When its transform or render data changes, call Update.
  3. Before the component or entity leaves the query, call Remove.

Use a change version to avoid a full render update when the source data did not change. Keep entity iteration and change detection in the ECS layer. Keep render-description conversion in RenderSystem.

Call Remove before component storage becomes invalid. The operation needs the stored RenderInstanceHandle.

Draw without an entity

Direct code does not use RenderSystem. It submits to the same RenderWorld.

Create a persistent instance when the code owns a long-lived object. Call DrawMeshOnce or DrawSpriteOnce when the object exists for one frame.

Rendering::MeshInstanceDesc desc{};
desc.mesh = customMesh;
desc.material = customMaterial;
desc.transform = transform;

renderWorld.DrawMeshOnce(desc);

This path does not create an entity. It still uses the same sorting, layer filtering, resource resolution, and backend execution.

Scene status

Scene and GameObject are minimal. They do not provide the full ECS integration. Do not place graphics-backend work in these classes.
