Diagnostics and tests

Use the profiler, memory tracker, log, and graphics tests to locate frame and resource failures.

Profiler

The update loop starts and ends one profiler frame. Scoped timers record engine work such as rendering, ImGui, frame submission, and presentation.

The profiler UI reads this captured data. Open the ImGui debugger to inspect frame time and individual scopes.

  • Press F5 to pause or resume profiler capture.
  • Press F6 to export frame statistics.

If the profiler UI has no frame data, first confirm that Profiler::BeginFrame and the matching frame-end operation still run in the engine update loop.

Memory::ResourceUsage

The memory tracker records allocations and per-frame totals in supported builds. The engine starts the memory frame with the profiler frame.

Use the tracker to find unexpected allocation growth and resources that remain live after shutdown.

DebugConsole

debug/debug.hpp and debug/debug.cpp provide engine logging and the debug console. Backend operations log context when initialization or a frame operation fails.

Keep the first failure message. Later failures can be results of the first error.

Graphics API tests

Debug startup calls Tests::RunGraphicsApiTests(). The main test source is GameEngine/src/tests/graphics_api_tests.cpp.

  • Resource table tests verify generations and stale-handle rejection.
  • RenderWorld tests verify persistent and one-frame data, filtering, sorting, updates, and destruction.
  • Renderer tests use a fake graphics device to verify frame results and resource invalidation.

The fake device lets renderer tests run without OpenGL or Vulkan. Backend behavior still requires a real backend run.

Trace a frame failure

  1. Read the first graphics error in the debug log.
  2. Identify whether the failure came from BeginFrame, recording, EndFrame, or Present.
  3. Check the returned FrameStatus.
  4. Confirm that the engine did not continue an invalid frame.
  5. For Vulkan, check image acquisition, swapchain state, and device-loss errors.
  6. For OpenGL, check context state and the first OpenGL error.

Trace an incorrect image

  1. Confirm the render item visibility and layer mask.
  2. Confirm the selected mesh, material, texture, and sampler handles.
  3. Confirm that the asset cache resolved valid GPU handles.
  4. Check frame constants and draw constants.
  5. Check blend, depth, viewport, and scissor state.
  6. Compare the same item on OpenGL and Vulkan.

If only one backend fails, inspect its state translation. If both backends fail, inspect the render description, asset data, or renderer command order.
