TheEngine / Graphics

Graphics system

namespace Graphics defines the backend-neutral resource, command, frame, and presentation contracts.

API boundary

Rendering code uses IGraphicsDevice, IGraphicsCommandList, typed handles, and description structures. Backend code converts these values into native graphics operations.

Renderer→ graphics descriptions→ IGraphicsDevice→ backend implementation

A public graphics header must not require an OpenGL or Vulkan type. Put native types in the backend directory.

Frame contract

IGraphicsDevice prepares, submits, and presents each frame. It returns a status after each frame operation.

Success
Continue the current frame.
Skip
Do not record or present the current frame.
ResizeRequired
Rebuild size-dependent state and start a later frame.
DeviceLost
Stop rendering. The graphics device is not usable.
Fatal
Stop the engine loop because the frame failed.

Check the returned FrameStatus before the next frame operation. Do not present a frame that did not complete submission.

Typed handles

A GPU handle contains a table index, generation, and device owner. The generation rejects stale access. The owner prevents a handle from one device from being used with another device.

The main types are GpuBufferHandle, GpuTextureHandle, GpuSamplerHandle, GpuShaderHandle, and GpuPipelineHandle.

Handles do not own resources. The graphics device owns the native resource until its matching destroy operation.

Descriptions and state

Description structures carry all data required to create a resource or record a command. They keep the API independent from native graphics structures.

The current API supports triangle, line, and point topology. It supports no blend, alpha blend, additive blend, premultiplied alpha blend, and multiply blend. It also supports viewport, scissor, depth state, vertex layouts, index formats, frame constants, and draw constants.

Resource lifetime

  • Create a resource before its first command use.
  • Keep it valid until all submitted commands stop using it.
  • Invalidate asset-backed GPU resources outside an active frame.
  • Call WaitIdle before shutdown destroys shared device state.
  • Destroy resources before the device shuts down.

Current scope

The scope is intentionally small. The API supports one swapchain color target and one backend-owned depth target. Each draw uses one texture and one sampler.

The API does not provide compute commands, instanced draws, indirect draws, multiple color targets, or shadow passes. Add one of these features only when a user-facing render requirement needs it.
