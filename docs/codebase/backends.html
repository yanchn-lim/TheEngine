OpenGL and Vulkan

Both backends implement the same graphics contract. Rendering and asset code do not select backend-specific operations.

Common contract

Graphics::CreateGraphicsDevice returns an IGraphicsDevice. Graphics::CreateImGuiBackend returns a matching IImGuiBackend. The engine uses these interfaces for the complete frame.

Both devices provide the same typed GPU handles, resource descriptions, command order, frame results, resize entry point, and shutdown entry point.

OpenGLGraphicsDevice

OpenGLGraphicsDevice targets OpenGL 4.6. GLFW creates the OpenGL context. GLAD loads the OpenGL functions.

The command-list methods apply state and issue draw calls when the renderer calls them. The backend converts graphics descriptions into OpenGL objects and state changes.

Frame behavior

  • BeginFrame prepares immediate command execution.
  • EndFrame completes the logical frame.
  • Present swaps the GLFW window buffers.
  • OnResize updates size-dependent state.

VulkanGraphicsDevice

VulkanGraphicsDevice targets Vulkan 1.3. It requires dynamic rendering and synchronization2 support. It records graphics commands into native command buffers.

The backend uses two frames in flight. Each frame owns command, synchronization, and submission resources. The swapchain owns its images and views. The graphics device creates one depth target for each swapchain image.

Frame behavior

  • BeginFrame waits for a frame resource and acquires a swapchain image.
  • BeginRenderPass starts Vulkan dynamic rendering.
  • EndFrame ends command recording and submits the command buffer.
  • Present sends the acquired image to the presentation queue.

Resize and recovery

The Vulkan backend marks a resize when image acquisition or presentation returns an out-of-date or suboptimal result. It rebuilds the swapchain before a later usable frame.

The device returns ResizeRequired when the current frame cannot continue. It returns DeviceLost for the matching Vulkan error. Other unrecoverable errors return Fatal.

The OpenGL backend does not rebuild a swapchain. It uses the GLFW framebuffer size and updates the viewport through the common command interface.

ImGui backends

The engine creates the ImGui context once. The selected IImGuiBackend handles native initialization, new-frame work, draw-data recording, and shutdown.

The OpenGL ImGui backend supports platform viewports. The Vulkan ImGui backend renders the same editor and profiler data in the main render path, but it does not report platform viewport support.

Profiler timing data is backend-neutral. The engine update loop records the timers before the ImGui view reads them.

Select and test a backend

Pass --opengl or --vulkan to the executable. Embedded applications can set Ludus::EngineConfig::rendererBackend before they construct the engine.

When you add a graphics feature, test the same render case on both backends. A backend must translate the common contract. It must not change the front-facing render API.
