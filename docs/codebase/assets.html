TheEngine / Assets

Assets system

The asset layer owns CPU data. The graphics layer owns GPU data. RenderResourceManager connects the two layers.

Resource flow

AssetManager→ asset handle→ RenderResourceManager→ GPU handle→ IGraphicsDevice

A render description stores an asset handle. The renderer requests a GPU handle from RenderResourceManager. The manager creates the GPU resource on the first request and returns the cached handle on later requests.

Asset registry model

For the complete contract, read the AssetManager reference.

AssetManager provides the central access point for CPU assets. Separate registries own each asset category.

TextureRegistry
Stores texture records and pixel data.
ShaderRegistry
Stores shader source and compiled shader data.
MeshRegistry
Stores vertex data, index data, and vertex layout data.
MaterialRegistry
Stores shader, texture, sampler, and render-state choices.
ModelRegistry
Stores imported model data and its mesh references.

Each registry returns a typed handle. The handle identifies one record without exposing its storage address.

Asset handles

The main types are TextureHandle, ShaderHandle, MeshHandle, MaterialHandle, and ModelHandle.

An asset handle and a GPU handle are different concepts. An asset handle identifies CPU-owned content. A GPU handle identifies a resource created by one graphics device.

Import and primitive data

The OBJ importer reads model files through tinyobjloader. The model importer registry selects an importer for a supported source path. The mesh registry stores the resulting vertex and index data.

The primitive mesh code creates built-in 2D mesh data without a source file.

A shader asset can store GLSL source and SPIR-V data. This arrangement lets OpenGL and Vulkan use the same logical shader asset.

RenderResourceManager

The manager converts asset descriptions into device descriptions. It then calls IGraphicsDevice to create buffers, textures, samplers, shaders, and graphics pipelines.

The manager caches the returned GPU handles by asset handle. This cache prevents duplicate GPU resources when many render items use the same asset.

Material resolution

A material selects its shader and fixed graphics state. It can also select a texture and sampler. The manager combines this data with mesh layout data when it resolves the graphics pipeline.

Invalidation

Invalidate a cached GPU resource when its source asset changes or is removed. The renderer provides invalidation entry points for textures, shaders, meshes, and materials.

  1. Finish the active frame.
  2. Call the matching renderer invalidation operation.
  3. Update or remove the CPU asset.
  4. Let the next render request create the new GPU resource.

Do not invalidate a GPU resource during an active frame. Recorded commands can still reference it.

Shutdown

RenderResourceManager::Shutdown destroys all cached GPU resources. The engine calls it before the graphics device shuts down.
