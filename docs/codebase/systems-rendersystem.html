RenderSystem

Converts ECS component lifecycle events into persistent RenderWorld instances.

Responsibility

Reads
Entity IDs, transforms, and render component data.
Creates
Persistent descriptions in RenderWorld.
Stores
The returned runtime handle and change version in the component.

Member functions

Add(entityId, transform, component, ...)
Builds a description, creates an instance, and stores its handle.
Update(entityId, transform, component, ...)
Applies changed source data to an existing instance.
Remove(component)
Destroys the instance and clears the runtime connection.

Mesh and sprite components use separate overloads. The sprite overload accepts a fallback material.

Required lifecycle

  1. Call Add when a matching component enters the query.
  2. Call Update when its transform or render data changes.
  3. Call Remove before the component or entity leaves the query.

Usage rules

  • Keep iteration and change detection in the ECS layer.
  • Use change versions to avoid unchanged updates.
  • Do not serialize runtime handles or render versions.
  • Call Remove before component storage becomes invalid.

The adapter exists, but a complete ECS lifecycle dispatcher does not call it yet.

Related types

Rendering::RenderWorld, MeshRendererComponent, SpriteComponent, and Transform2D.
